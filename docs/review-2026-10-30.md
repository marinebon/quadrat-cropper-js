# Code review and user-requested changes — 2026-10-30 (v1.5.3 → v1.7.0)

> **Start with [`CHANGES-1.5.3-to-1.12.0.md`](CHANGES-1.5.3-to-1.12.0.md)**, the consolidated, theme-ordered
> explanation of every change up to v1.12.0. This file is the original
> chronological log, kept for reference.

Review of the browser app (`js/*.js`; the detector internals in `qd.js` are
untouched apart from exported helpers) plus changes requested by the field
team while testing it. Branch: `review/claude-bugfixes-2026-10`. Each change
is commented in place. Rows marked **User report / User request** came from
testing the live site and the branch on real photos and a real Drive.

> **Tested** in headless Chromium against a local server: the 16 repo
> fixtures (same results with the new worker pool as with the sequential
> path), a mocked Google sign-in + Drive v3 API (subfolders, Shared drives,
> shortcuts, a failing file, a 60-photo folder with network latency), real
> Canon CR2 / Nikon NEF samples and a synthetic Olympus ORF. Drive with a real
> Shared-drive folder was confirmed by the field team (v1.5.5). The detector
> core in `js/qd.js` is unchanged — only new exported helpers (`fitSquare`,
> `fitInside`, `scaleQuad`) and `VERSION` — so `npm test` expectations should
> hold; it could not be run in the review environment, CI runs it on the PR.

## Found but NOT changed (need a decision from the maintainer)

1. **`annotations.csv` joins are misleading.** CoralNet exports one row per
   point; the index keeps the *last* point row per image, so the manifest gets
   `Row/Column/Label` of one arbitrary point. Suggest skipping CSVs whose name
   key is not unique, or only joining `metadata.csv`-like files.
2. *(fixed, see #13)*
3. *(fixed, see #14)*
4. **Zip / Drive entries lose their folder.** `name.split('/').pop()` → two
   `IMG_0001.JPG` in `HIGH/` and `MID/` become the same name (export dedupes
   to `_crop_2`, but which strata it was is lost). Consider keeping the
   relative path in the manifest.
5. **Public single-file links** are saved as `drive_<id>.jpg` and fetched via
   `lh3.googleusercontent.com/...=s0`, which likely strips EXIF (date/GPS/
   orientation) — and the original filename is lost, so metadata parsing
   cannot work for that path.
6. **`warpToSquare`** samples at integer output coordinates (half-pixel shift)
   and uses plain bilinear when shrinking to the 1600 px cap (some aliasing on
   barnacle-scale texture). Minor; area-average or a pre-blur would help
   if crops feed CoralNet classification.
7. **Editor Apply accepts any quad**, including self-intersecting / non-convex
   ones (e.g. two markers swapped) — a convexity check before re-crop would
   prevent a scrambled crop being exported as "manual".
8. **`clearAll` during processing** now stops after the in-flight image (thanks
   to fix 1), but the export button and progress bar are not reset until it
   finishes.
9. `drive.js` `loadPicker` never sets `tokenInfo.pickerReady = true`, so
   `gapi.load('picker')` runs on every pick (harmless).

10. **AP161656 fails in the browser** ("no plausible quadrilateral among
    fitted edges") on both v1.5.3 and this branch, although `expected.json`
    marks it as a crop ≥ 0.80. The suite decodes with jpeg-js; the browser
    decodes with `createImageBitmap` — the two paths apparently still differ
    on this image. Worth adding a browser-decoded check to CI.
11. *(done in #31: native warp + one common export size)*
12. Manual crops are not forced square (only the suggested crop is). A
    "lock square" toggle in the editor could be added if wanted.
